# D-05b: expectation anchored to observed state (lead, Tier 2, in progress)

## Problem (measured, SIMULATION, recorded demo runs, 48 h, 5-min ticks)
Every run, `normal_week` included, raises one incident at tick 295 (R_D2_CUSUM + R_MULTI_SENSOR on all sensors, hypothesis unknown). The expectation (`telemetry/expectation.py`) is open-loop: one 48 h hydraulic run on forecast demand with its own tank-level pump controls. After day 1 its pump switching differs from the real run, so tank levels and every pressure and flow drift: level residual sd 0.045 m on day 1 against 1.27 m on day 2; pressure 0.115 m against 1.28 m. The CUSUM calibrates on day 1 (ticks 0-287), so day 2 fires everywhere.

## Prototype (`D-05b-prototype.py.txt`, run as `python anchor_proto.py 12 export <run> --store ... --out ...`)
Hourly segments (12 ticks): each segment starts from the latest valid observed tank level (causal) and the previous segment's pump states.
- Result: median day-2/day-1 residual spread ratio 1.0 (was about 10); but the flow sensors next to the tanks (`sensor_flow_001/002/004`) still diverge, and one incident still fires at tick 298.
- Second attempt (pump state from the observed level trend inside the control band): worse; `sensor_flow_002` (a standby pump, measures 0) is expected at 113 L/s from tick 289. Prototype bug in the pump-state seeding (`initial_status` set as a string on a WNTR pump, and the standby is not excluded); not yet found.

## Design to finish
1. `expected_readings(network, sensor_set, forecast, observed=None, segment_ticks=12)`: with `observed` (telemetry readings, causal use only: tick <= segment start), simulate hourly segments from observed tank levels; without it, today's behaviour (kept for tests).
2. Pump states per segment: duty pumps from their level control and the observed level (below on -> on, above off -> off, inside the band -> the previous segment's end state); standby pumps stay closed (no failover in the expectation). Set the status through `build_model` (a new optional `initial_open` mapping), never by writing strings to WNTR objects.
3. Acceptance: zero incidents on `normal_week` seeds 1-3; each fault run raises one incident within 2 h of its onset; residual spread ratio day 2/day 1 <= 2 on every sensor of `normal_week`; deterministic; memory per export <= 1.5 GB.
4. Re-record (`make demo-record`), re-pack, update `docs/DEMO_RUNBOOK.md`.
