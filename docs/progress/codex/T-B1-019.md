## Deterministic element-choice rules

Build `ProceduralCapitalProvider().build(1)` offline. District centroid means arithmetic mean of all built junction coordinates belonging to that district; network centroid means arithmetic mean of all built junction coordinates. This includes zero-demand equipment/inline-valve junctions. Ties always use lexicographically smallest element id.

- Fire: `residential_inner` exists and has residential land use; choose its junction with minimum Euclidean distance to its centroid: `j_0088`. No fallback district used.
- Gradual leak: choose distribution pipes with both endpoint junctions in `business`; minimize point-to-straight-segment distance from the district centroid: `p_0276`.
- Sudden leak: same pipe rule for `residential_outer`: `p_0124`.
- Burst: choose among transmission pipes by point-to-straight-segment distance from network centroid: `p_0229`. The contract requires `final_area_cm2`; used the instructed **ASSUMPTION** 50.0 cm².
- Outage: count junctions reachable from each station discharge in the undirected pipe/valve graph, excluding pump links and any shared-source path through pumps. Each station reaches all **CALCULATED** 260 junctions. Break the station tie by station id (`station_east`), then choose its lexicographically first duty pump (`station_east_duty_0`). This reachability count is a structural proxy, not a hydraulically determined service area. Standby behavior belongs to T-B1-017.

These rules are independently recomputed by offline tests. The ids are written literally into JSON; the loader performs no network computation, hydraulic simulation or reference lookup.
