## What changed

- `platform/ug_cli`: `ug export <run_id> --store <dir> --out <runs_dir>` discovers the water adapter through the registry. It writes an atomic D-07 bundle under `<runs_dir>/<run_id>`, validates every payload against the existing local contracts, repeats identical exports as a no-op, and refuses to overwrite different output. Files: view `manifest.json`, `network.json`, `readings.json`, three series per selected sensor (SENSOR_SIM / MODEL / CALCULATED), and `incidents.json`. No decision is emitted without defensible physical exposure estimates.
- `domains/water/src/ug_water/adapter.py`: optional `export_view` bridge verifies the network and assumption hashes plus recorded model/library versions; reconstructs only selected sensor channels for the measurement model; discards hidden tags; builds independent forecast-driven expectations. Arrow filtering happens before Python row materialization to limit memory. Expectations use the repository's existing six-decimal output precision before quality/D2/residual calculations, eliminating observed machine-epsilon WNTR differences between exports. Procedural standard tier is explicitly versioned and targets 800 junctions / 1,050 pipes; existing lite behavior stays unchanged.
- `ug run` accepts `--duration-hours`; `make demo-baseline` runs normal_week, procedural standard, seed 1, 48 hours, and exports it. All numerical thread limits are set inside the target. Output is ignored at `var/demo-runs/`.
- API entry point reads `UG_RUNS_DIR` (default `var/demo-runs/views`) alongside the existing static mount. Existing health/static serving and `make up` deployment files are unchanged.
- `frontend/src/app/api.ts`: same-origin `/api/runs/...` requests, runtime guards typed against generated network/series types, recursive truth-key rejection, explicit fixture reasons, missing values retained as unavailable. One shell-owned load is shared across the two screens. The map shows only measured sensor elements, with other elements unavailable. Command Center shows the latest recorded sensor readings and the map. Shell shows run id, run fidelity and REPLAY; fixtures retain the fixture marker.
- Vite's only change is `server.proxy` for `/api` to the existing local API port.
- Tests: tiny one-junction, two-hour export with a private event sentinel; layout, labels, byte equality, overwrite protection, network mismatch, no decision; real procedural CLI export through the API and the D-07 recursive truth walk over every file; frontend malformed payload/fallback/missing data tests; stubbed replay browser spec.

## How to run

With the repository packages installed in the current environment:

```sh
make demo-baseline
cd frontend && npm run build
# From the repository root, in another terminal:
UG_STATIC_DIR=frontend/dist UG_RUNS_DIR=var/demo-runs/views .venv/bin/python -m ug_api
```

Open `http://127.0.0.1:8080/` or `/#/map`. For Vite development, run `cd frontend && npm run dev` alongside the API; `/api` is proxied to port 8080. This checkout has **no existing `make dev` target**. No absent target was silently represented as tested.

An existing run can be exported independently:

```sh
.venv/bin/python -m ug_cli export <run_id> --store var/demo-runs/store --out var/demo-runs/views
```

The original restricted store remains the reproducibility source. The bundle manifest is explicitly a sanitized view manifest: faults/cross-domain injections and restricted output hashes are removed. It must not be used as an original reproduction manifest.
