## Known limits and integration decisions

- `frontend/src/ui/Metric.tsx` was absent. Numbers use the requested local `Value.tsx`; replace it with Lane A's Metric during integration. Evidence drawer records/click wiring remain Lane A/W-01 work; this card supplies evidence attributes and visible reading labels.
- `SensorWhatIf` is a UI type, not a new contract. No contracts or generated types changed. The API/measurement-layer mapping must be done after the approved API contract lands.
- Drift is additive, in physical sensor units per hour: `baseline + drift_per_hour * (tick - from_tick) * TICK_MINUTES / 60`. It preserves null readings. Disable sets null/missing. Stuck repeats the current reading at the selected cursor. Stuck is disabled when that reading is unavailable. The preview chart includes readings after the cursor, explicitly explained in the UI, so the effects are visible immediately.
- The quality column intentionally summarizes flags anywhere in the displayed preview, including historical missing stretches; it is titled “Quality flags in preview”. Quality scores are illustrative fixture rules (`quality.score.v1`), never production detector output, and are not displayed.
- Chart callers supply ordered points with the same physical unit per chart. No statistical band is invented for sensor fixtures; the optional band is exercised by the chart unit test for future forecast callers.
- Sensor identifiers use `code[data-identifier]`; the cursor uses `time` with the tick UTC timestamp and index. The drift input has no evidence wrapper. Reading values remain SENSOR_SIM and quality flags are CALCULATED. Elapsed-time axis labels carry the series label as requested.
