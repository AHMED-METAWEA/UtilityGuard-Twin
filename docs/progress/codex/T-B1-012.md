## Decisions and limits

1. Configuration is explicit: `DemandModel.from_file("assumptions/demand_v1.yaml")`, then `model.truth(network, timebase, seed, calendar)` and `model.forecast(...)`. Methods are pure evaluations over the immutable assumption set. This avoids repository-relative defaults, hidden configuration caches and dependence on the caller's working directory. Strict loading delegates to `ug_core.assumptions`; no second loader.
2. Provider `base_demand` is preserved in m3/s, including the provider's zero-demand junctions. Profile normalization changes dimensionless multipliers only. Normal and Ramadan profiles are normalized separately to mean one, and raw inputs remain available as ASSUMPTION records with evidence IDs and the full set hash.
3. `demand_ramadan_<land_use>_hXX` means hours after `iftar_hour_local`, with h00 at Iftar and a placeholder peak at h01. Diurnal hXX is local clock hour. Both interpolate linearly with daily wrap. The convention is documented in the YAML and model, and tests change Iftar to prove the peak moves.
4. Fixed UTC offset is added to UTC ticks using `timedelta`; calendar windows are naive local datetimes and half-open `[start, end)`. Simultaneous events multiply; fire flows add after stochastic demand. Calendar entries are sorted for deterministic accumulation. Identifiers are validated against the network in both paths, but event/fire effects never enter forecast values.
5. AR(1) sigma is stationary standard deviation, not innovation SD. The initial error is drawn from the stationary distribution; innovations use `sigma * sqrt(1 - phi**2)`. Phi applies per hydraulic tick. Separate exact named streams are tested per zone. Gaussian errors are unbounded: a configuration/seed producing a non-positive stochastic multiplier raises instead of clipping. This limitation is documented; default placeholders passed all sampled seeds.
6. The forecast never calls truth or `_truth_noise`; its conservative AST call graph and runtime tripwire tests prove separation. Both paths share only deterministic expectation code and the generic AR(1) algorithm. Changing an unused noise parameter preserves the other path's **values**, but its series hash changes because provenance deliberately hashes the entire assumption set. Adding events/fires with the same assumption set preserves the forecast hash.
7. `DemandSeries` uses detached bytes-backed NumPy storage: callers cannot mutate the source buffer or re-enable writeability. Hash content includes the axis, sorted junctions, unit, evidence label and assumption-set hash; each value uses `round_for_hash`. NumPy 2.4.6 was installed for the recorded golden case. The existing `SeedStreams` version caveat remains applicable across NumPy releases.
8. No new dependencies or external APIs. No design decision was blocked and no change outside the allowed files was required. Parameters remain synthetic placeholders; no ACUD data or field validation is claimed.
