## Lead decisions and implementation details

1. `measure_with_delivery(truth, seeds)` returns an ordinary core `TelemetrySeries` plus a read-only mapping of sensor id to delay tuples. `measure()` returns only the series. Delays are drawn on every tick, including missing ticks. `to_readings(series, network, delays=None, quality=None)` includes `delivered_at` only when delays are supplied; `assess(..., delivered_delay_s=...)` accepts the same mapping.
2. `rtu_group(sensor, network)` is the single routing function: junction sensor -> junction zone; pipe/pump/valve -> START junction zone, otherwise END junction zone, otherwise link id; level -> tank id. Cross-zone links prefer START. Tests cover junction, both endpoint branches, fallback, pump, valve and tank. Unsupported placements fail explicitly.
3. `as_faults(whatifs, step_seconds, horizon_ticks)` uses start `from_tick * step_seconds / 3600` and duration `(horizon_ticks - from_tick) * step_seconds / 3600`. It refuses `from_tick >= horizon_ticks`. Measurement uses ceil onset with a two-ULP correction at integer boundaries to avoid floating round-trip delays. Fault ends are exclusive.

## Limits and review focus

- Delivery delays are uniformly drawn **whole seconds**, inclusive of the configured interval, because the unchanged timestamp contract accepts whole seconds only. Serialization rejects fractional delays rather than silently truncating. This is a synthetic assumption, not a measured delivery distribution.
- Each sensor draws standard-normal noise, a base-dropout uniform, a fault-dropout uniform and an integer delivery delay every tick. Concurrent fault-dropout probabilities combine as `1 - product(1 - probability)`; base dropout remains independent. Canonical payload ordering breaks identical type/sensor/start ties.
- Stuck captures the first active pre-dropout candidate, after noise/offset/drift. Thus it still has a value to hold if that tick is subsequently hidden by dropout/outage. Concurrent stuck faults apply in canonical order. This follows the card's prescribed stage order.
- Drift is rate times elapsed hours since the configured start; at an exactly aligned onset its initial increment is zero. The non-aligned onset test proves it starts at ceil, and disable what-ifs prove exact aligned tick round trips.
- Q08 uses the specified first 288 ticks for calibration, excluding missing samples. The six-hour detection test starts drift after that clean calibration window. Faults already present during calibration can inflate MAD and delay detection; this implementation does not claim a universal detection deadline. No calibration residuals -> the specified `2 * quantum` floor. Missing ticks leave EWMA unchanged.
